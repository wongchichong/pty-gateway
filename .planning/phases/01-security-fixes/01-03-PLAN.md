# PLAN: Add Rate Limiting Middleware

## Objective

Implement rate limiting to prevent users from spamming commands and potentially overwhelming the PTY service or messaging APIs.

## Context

**Problem**: No rate limiting exists. Users can send unlimited commands, which could:
- Overwhelm the PTY service
- Hit Telegram/Discord API rate limits
- Enable DoS attacks
- Consume excessive resources

**Solution**: Add per-user rate limiting with configurable limits.

### Task 2: Create Rate Limiter Module

**File**: `src/rate-limiter.ts` (new file)

```typescript
import { RateLimiter } from "limiter";
import type { ChannelType } from "./channels/types.js";

// Rate limit configuration per channel type
const RATE_LIMITS: Record<ChannelType, { tokens: number; interval: "minute" | "second" }> = {
  telegram: { tokens: 5, interval: "minute" },
  discord: { tokens: 10, interval: "minute" },
  whatsapp: { tokens: 5, interval: "minute" },
  slack: { tokens: 10, interval: "minute" },
  matrix: { tokens: 10, interval: "minute" },
  irc: { tokens: 20, interval: "minute" },
  line: { tokens: 5, interval: "minute" },
  nostr: { tokens: 10, interval: "minute" },
  twitch: { tokens: 20, interval: "minute" },
  wechat: { tokens: 5, interval: "minute" },
  googlechat: { tokens: 10, interval: "minute" },
  msteams: { tokens: 10, interval: "minute" },
  nextcloud: { tokens: 10, interval: "minute" },
  synology: { tokens: 10, interval: "minute" },
  tlon: { tokens: 10, interval: "minute" },
  webchat: { tokens: 30, interval: "minute" },
  signal: { tokens: 5, interval: "minute" },
  imessage: { tokens: 30, interval: "minute" },
  http: { tokens: 10, interval: "minute" },
};

// Track limiters per user per channel
const userLimiters = new Map<string, RateLimiter>();

function getLimiterKey(channel: ChannelType, userId: string): string {
  return `${channel}:${userId}`;
}

export function checkRateLimit(channel: ChannelType, userId: string): { allowed: boolean; remaining: number } {
  const key = getLimiterKey(channel, userId);
  const config = RATE_LIMITS[channel] || { tokens: 5, interval: "minute" as const };

  let limiter = userLimiters.get(key);

  if (!limiter) {
    limiter = new RateLimiter({
      tokensPerInterval: config.tokens,
      interval: config.interval,
    });
    userLimiters.set(key, limiter);
  }

  const allowed = limiter.tryRemoveTokens(1);
  const remaining = limiter.getTokensRemaining();

  return { allowed, remaining };
}

export function getRateLimitMessage(channel: ChannelType): string {
  const config = RATE_LIMITS[channel] || { tokens: 5 };
  return `⚠️ Rate limit exceeded. You can send ${config.tokens} commands per minute. Please wait before sending more commands.`;
}

// Cleanup old limiters every 5 minutes to prevent memory leaks
setInterval(() => {
  // Remove limiters that haven't been used in 5 minutes
  // (RateLimiter doesn't expose lastUsed, so we just clear all)
  // In production, implement proper LRU cache
  if (userLimiters.size > 1000) {
    userLimiters.clear();
    console.log("[RateLimiter] Cleared cache (size > 1000)");
  }
}, 5 * 60 * 1000);
```

### Task 3: Integrate Rate Limiter into Router

**File**: `src/router.ts`

Add rate limiting check in `handleChannelMessage`:

```typescript
import { checkRateLimit, getRateLimitMessage } from "./rate-limiter.js";

// In handleChannelMessage method, add after message logging:
async handleChannelMessage(msg: ChannelMessage): Promise<void> {
  console.log(`[${msg.channel}] 📨 Message received: "${msg.text}"`);

  // Rate limiting check
  const { allowed, remaining } = checkRateLimit(msg.channel, msg.userId);
  if (!allowed) {
    const channel = this.channels.get(msg.channel);
    if (channel) {
      await channel.sendMessage(msg.chatId, getRateLimitMessage(msg.channel));
    }
    console.log(`[${msg.channel}] ⚠️ Rate limit exceeded for user ${msg.userId}`);
    return;
  }

  console.log(`[${msg.channel}] ✅ Rate limit check passed (${remaining} remaining)`);

  // ... rest of existing logic
}
```

## Configuration

**Environment Variables:**
- `RATE_LIMIT_TOKENS` — Number of commands allowed per interval (default: 5)
- `RATE_LIMIT_INTERVAL` — Time interval: "minute" or "second" (default: "minute")

**Per-Channel Defaults:**
- Telegram: 5/minute (conservative for mobile users)
- Discord: 10/minute (desktop users, higher tolerance)
- IRC: 20/minute (traditional IRC norms)
- WebChat: 30/minute (direct access, higher limits)

## Performance Impact

- **Memory**: Minimal - one RateLimiter object per active user (~100 bytes each)
- **CPU**: Negligible - simple token bucket algorithm
- **Latency**: < 1ms per message for rate check
